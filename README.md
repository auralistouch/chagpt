# 比特币十分钟观察台 · v1.6

本机中文观察工具：使用 **币安 BTCUSDT 价格指数**研究方向，保留原五项指标、样本门槛、Bark 配置、声音与桌面提醒。**不自动下单，不部署云服务，没有已证明的盈利优势。** Coinbase 仍可用于独立现货研究，不发送币安合约提醒。合成演示永远等待。

## 这次修了什么

- 旧版把现货价格当作结算参照，并用下一分钟开盘至第十分钟收盘模拟结果。新版将指数价格、现货量能分开，按下一秒开仓再过600秒到期处理时间。
- 一分钟K线无法提供任意秒位的精确开仓/到期指数。页面明确显示**价格范围和保守界限**，不再将分钟收盘价伪装成真实结算价或精确胜率；另有精确端点离线验证工具。
- 原五项指标阈值、后段至少30笔及 Wilson 保守下界门槛保留。不通过就记录原因，不为了凑每天几次而降低要求。
- 手机每次检查会记录指标、单项失败原因、样本数、统计门槛、行情年龄、推送尝试与结果。页面手机区域展开“逐次检查与推送记录”即可查看。
- 修复手机与网页75/90秒不一致；指数快照另须小于15秒。正式提醒至少相隔601秒，同一信号不重发。推送前保存去重状态；超时可能已送达，仍不自动重发。

## 官方规则与来源

核对日期：2026-10-31。以下为本工具采用的产品口径，实际订单及平台最新规则优先。

1. BTCUSDT 事件合约比较开仓与到期的**价格指数**；Higher 为到期高于开仓，Lower 为低于开仓。
2. 提交后的下一秒取得开仓时间及指数，十分钟从开仓时间起算600秒。例如17:59:59提交，18:00:00开仓，18:10:00到期。不能把提交瞬间价格直接与601秒后比较；任意提交秒位均可研究，不限整十分钟。
3. 方向正确按提交订单时确认的赔付额结算，方向错误亏已付本金；平价返还本金，净盈亏0。实际赔付比例可能变化，80%只是当前验证假设：投入1，赢+0.8、输-1、平0。没有平价时盈亏平衡胜率为55.56%。
4. 合约不能提前平仓。工具只发观察提醒，不调用交易接口。官方说明事件合约通过Android/iOS应用使用。

官方资料：

- [事件合约FAQ（含开仓、结算、平价及动态赔率）](https://www.binance.com/en/support/faq/detail/172247f1c4b8401ab106fb63900f3825)
- [价格指数与标记价格说明](https://www.binance.com/en/support/faq/detail/360033525071)
- [币安市场数据接口：Index Price Klines / Mark Price](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)
- [Bark官方接口文档](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md)

行情来源固定为：

| 用途 | 来源 |
| --- | --- |
| 指数时间 | `https://fapi.binance.com/fapi/v1/time` |
| 指数OHLC | `/fapi/v1/indexPriceKlines?pair=BTCUSDT&interval=1m` |
| 当前指数 | `/fapi/v1/premiumIndex?symbol=BTCUSDT` 的 **indexPrice** 字段 |
| 原有量能条件 | `https://api.binance.com/api/v3/klines?symbol=BTCUSDT&interval=1m` 的现货成交量 |

`markPrice`、现货成交价、期货成交价、`estimatedSettlePrice`均不替代指数。指数K线的第六字段是Ignore，不是成交量；直接拿来计算原量能条件会使其永远无法通过。所有价格使用指数OHLC，只有量能使用明确标注的现货量；按分钟严格对齐，缺失、重复、越界则暂停，不补造价格、不切换来源。

公开指数是市场数据参照，并非账户订单成交/结算回报；实际开仓和到期仍须与币安订单记录核对。接口网络可达也不代表产品交易资格。

## 安装及从旧版更新

需要 Python 3.10+，主程序仅标准库，无需安装第三方依赖。

1. 旧终端按 Control+C停止。下载本仓库 `codex/btc-ten-minute-signals` 分支ZIP，解压到新文件夹。不要删除旧程序或配置。
2. macOS双击 `start.command`；Windows双击 `start.bat`；Linux或终端运行 `sh start.sh`。浏览器打开 `http://127.0.0.1:8000`，页头应显示v1.6。
3. 默认选择币安BTCUSDT指数、80%验证赔率。点击获取分析。首次获取三天数据，随后增量更新。指数或量能任一接口不通都会暂停。
4. 原Bark地址、启用状态、来源、赔率、去重时间仍从原配置文件读取，不需要重填地址；配置中的未知字段也会保留。原来保存了Coinbase或其他赔率的设置不会被偷偷改写，需手动切回币安指数和80%再保存。

配置默认位于 `~/.config/btc-observer/phone.json`，可通过 `BTC_OBSERVER_CONFIG_DIR`指定已有目录。文件权限600，目录700；不是加密存储。程序升级不清除配置。不要将Bark密钥、配置文件或含密钥的截图提交到GitHub。

## 手机、声音和桌面提醒

Bark地址仅填在本机网页密码框，点击“保存手机设置”。已有配置可直接发送标为测试的通知；测试不代表策略产生买点，不消耗正式提醒冷却期。`accepted`只代表Bark服务接受请求，不证明手机已展示。

Mac后端每次检查结束约30秒后再查，关闭网页仍可继续。终端必须运行，Mac须联网并保持唤醒；`start.command`保留原有`caffeinate -i`行为，不修改永久电源设置。合盖、睡眠、退出终端或断网会中断监测。手机无需与Mac使用同一网络。

网页声音、桌面通知、自动刷新保留原有本地存储偏好；刷新不会清除设置，手动停用也会保留。首次浏览器通知授权及声音解锁可能需要点击一次。网页失败后按5/10/20/40/60秒重试，来源切换和请求中会暂停旧方向；手机监测独立于网页刷新开关。

Bark和苹果推送系统会处理设备标识及观察内容。仅支持官方 `api.day.app`，不支持任意自定义服务器。配置接口仍只接受本机同源JSON POST；不要将服务端口公开。

## 怎样查24小时没有提醒

手机区域现在显示具体原因，展开记录可检查：

- `check_started`：每次后台检查开始，包括时间、来源与赔率。
- `check_result`：指标逐项通过情况、失败代码、行情年龄、后段样本/确定胜出数/端点不确定数及统计门槛。
- `check_blocked`：五项指标、样本不足、统计门槛、旧行情、非指数、重复或冷却期等具体拦截原因。
- `check_error`：失败阶段及安全错误类型；行情HTTP状态等结构化信息会保留，不记录远端错误正文或密钥。
- `push_attempt`与`push_result`：测试/正式分别记录；结果为`accepted`、`rejected`、`unknown`。最后一种不自动重发。

本机诊断文件与配置同目录的`logs/`下保存：`monitor.jsonl`加最多3个轮转文件，每个约5MB；`daily.json`保留最近31个有记录的UTC日。文件600，目录700；状态API不会返回密钥或整个配置。不要把日志永久写进仓库。

`daily_utc`统计实际检查数、五项全过的去重候选分钟、被拦截检查数、正式推送尝试/服务接受/拒绝/未确认数，测试另计。候选方向不等于正式提醒，接受不等于手机展示；断电、崩溃与文件写入失败可能使最后一条汇总不完整。UTC日与手机当地日期可能不同。

旧版没有逐次原因日志，不能事后从“持续检查”恢复昨天的全部拦截过程。Bark测试能到只证明测试链路可用。需用新版日志区分“没有候选”“验证未通过”“网络失败”和“推送未确认”。

## 策略与分钟区间验证

原五项条件不变：EMA20/50分离至少0.04%；看涨RSI52–68、看跌32–48；现货成交量≥此前20分钟均量1.1倍；ATR/价格0.03%–0.6%；3分钟动量和价格方向一致且距EMA20≤1.5 ATR。全部通过才进入统计检查。满足项数不是概率。

生产窗口仍为约三天，前2/3描述，后1/3检验。下一秒开仓、600秒到期的两个准确价格不包含在分钟K线中。因此只在所有可能开仓/到期价格都能赢时标为“可确定胜出”；不能确定的记为不确定，在门槛中保守按失败处理。开仓区间还包含提交分钟最后一秒导致的下一分钟边界。到期区间保守覆盖两分钟；不以收盘价或插值伪造端点。模拟区间每12分钟最多一笔，保证区间持有不重叠。

后段仍至少30笔，且 Wilson 95%下界大于 `1/(1+净收益比例)+2%`；80%时为大于57.56%。区间下界的意义依赖行情覆盖、样本代表性等假设，交易结果相关时统计区间仍可能偏乐观；这不是未来胜率保证。`profit_units`为区间最坏情形净盈亏，`profit_upper_units`为上界，回撤为保守情形路径的回撤；平价仅在整个区间完全同价时确定退款。非指数来源不能用这些数字验证币安合约。

这种修复**可能仍然长期没有正式提醒**，甚至因原来不确定结果不再被冒充精确结算而更少。没有证据就不放宽门槛。每天几次和更高胜率是研究目标，不是可以靠软件开关保证的结果。

## 在Mac验证真实行情与每日频次

在项目文件夹的终端运行：

```bash
python3 audit.py --days 30 --output work/index-audit.json
```

只读下载30天指数OHLC和独立现货量能，输出带SHA256的CSV和报告；不读取Bark配置，不发通知、不下单。可用`--days 3`先查连通性，最多90天。报告按时间分前段和后段，给出逐日UTC候选分钟及各项失败统计、保守界限；候选未经逐次生产统计门槛与去重，**不能当成历史正式推送次数**，也不能外推“每天几次”。真实运行的正式提醒次数看`daily_utc.signal_attempts`。

已有同格式指数数据可离线运行：

```bash
python3 audit.py --input work/index-audit.csv --output work/offline-audit.json
```

精确结算验证需要可核实来源、准确交易所时间戳的BTCUSDT指数样本（不能用现货或标记价）。CSV格式：

- 指数OHLC和现货量能：`time_ms,open,high,low,close,spot_volume`
- 精确指数样本：`time_ms,index_price`
- 可选任意提交时刻：`time_ms`

```bash
python3 replay.py --candles work/index-audit.csv --ticks work/index-seconds.csv --decisions work/decisions.csv --output work/exact-replay.json
```

不传`--decisions`时仅使用分钟边界作为采样计划，产品本身不限整分钟。每次按提交后下一秒及其600秒后严格匹配端点，用Decimal结算，平价0；缺少任一端点就标为未评分，不取最近价格，不插值。缺失仍计入覆盖率分母及保守统计分母。未评分不能算赢。跨前后段的持有不计入前段结果，缺失样本也保留不重叠时段，避免挑选赢家。

`replay.py`验证固定规则的候选方向，不重演生产端每次变化的统计门槛；报告明确标注`production_push_backtest=false`，不能把其交易次数说成真实推送次数。秒级数据的来源由提供者核实，列名本身不证明来源。

云环境目前可读写GitHub及运行离线测试；本次查询币安行情被环境网络策略403阻止，未完成真实历史收益或频次验证。没有用合成数据声称策略胜率提高。需要联网历史、足够多的独立后段样本及后续前瞻记录，才可评估候选改进是否同时提高净收益和有效频次。
