# BTC十分钟信号台 · v3.0

本机网页声音/桌面通知＋Bark手机看涨/看跌信号。新策略为 **顺向趋势＋真实回踩收回确认**，修正v2方向和回踩判定。只发提示，不登录币安、不下单、不部署云服务。没有已证明的盈利优势，不承诺成功率或每天次数。

## 更新与启用

1. 旧程序终端按Control+C停止，解压新版本到新文件夹。保留旧配置。
2. Mac双击 `start.command`；Windows双击 `start.bat`；或运行 `python3 app.py`。打开 http://127.0.0.1:8000 ，页头应为v3.0。
3. 数据来源选择币安指数，提醒模式选择 **“新版：顺向趋势＋回踩收回确认”**，点击获取分析。
4. 点击“保存手机设置”。Bark输入框留空会保留已保存地址；状态栏应显示新版模式。再发送手机测试，检查实际手机展示。
5. 网页首次使用点击“授权通知 / 启用声音”。网页偏好保留；手机后台不依赖网页打开，但终端须运行、Mac须联网并保持唤醒。休眠、合盖或退出终端会停止。

旧的手机策略设置不会自动改写，请明确按第3、4步保存。新建配置默认v3。改策略不会重置601秒信号冷却；设备密钥、未知配置字段和去重时间保留。测试通知不消耗信号冷却。

## 官方规则：单点指数，不是范围

本次重新读取币安英文事件合约FAQ，页面仍标注更新于2026-10-28 11:08。

- BTCUSDT事件合约比较开仓和到期的**价格指数单点值**；不是现货最新价、期货成交价或标记价格。
- 官方说明自2026-01-28起逐步采用提交后的下一秒作为开仓时间及指数，再计600秒到期。示例17:59:59提交→18:00:00开仓→18:10:00到期；不是任意毫秒提交一律601秒。
- Higher为到期指数更高，Lower为更低；平价返还本金、净盈亏0。实际开仓、到期和结果以币安订单为准。
- 赔付比例动态变化，在提交订单时锁定。默认80%只是净收益假设，不是官方固定赔率；无平价时对应盈亏平衡胜率55.56%。
- 最低投入5 USDT；公开FAQ写明每日亏损上限10,000 USDT，包含未平仓潜在亏损；用户日限额按UTC日重置。未平仓数量和单笔限制以应用Trading Rules/平台显示为准，可能调整。
- 不可提前平仓；FAQ仍写明通过Android/iOS应用使用。本工具没有账户资格、实时报价或订单API，不代替平台核查。

官方来源：

- [事件合约FAQ](https://www.binance.com/en/support/faq/detail/172247f1c4b8401ab106fb63900f3825)
- [价格指数与标记价格](https://www.binance.com/en/support/faq/detail/360033525071)

指数K线专属interval从1m开始；文档相邻其它成交价接口即使支持1s，也不能冒充秒级指数。第[5]字段为Ignore，不是成交量。程序只用fapi的indexPriceKlines和premiumIndex的indexPrice字段；不拿markPrice、现货或其它交易所替代指数。

## 为什么删除旧范围表

旧表用一分钟OHLC的高低范围包住无法确定的秒级端点，统计下界又把不确定按失败。它不是你的真实开仓/到期，不是实际亏损，也不是实际订单胜率。v3网页不再展示该表，不能靠更换统计口径宣称策略变好。

现在明确提供两种核算，均不影响信号触发：

### 你的订单单点核算

页面可下载CSV格式模板并选择整理好的订单CSV。**这是本工具格式，不保证币安原始导出文件能直接导入，需按订单记录对齐列名。** 不导入时真实订单胜率显示无数据。

列为：

```text
order_id,direction,open_time_ms,expiry_time_ms,open_index,close_index,net_payout,stake
```

- order_id为不重复编号；direction为UP/DOWN或看涨/看跌。
- 时间为整数毫秒，开仓至到期600秒；价格填写该订单的单点指数。
- net_payout是**该笔**净收益比例（例如0.8，不是80），stake为本金。按此计算净盈亏，不拿网页当前假设覆盖历史订单报价。
- 缺失开仓或到期指数可留空，记为未验证，不计胜负与盈亏。平价单列净盈亏0；方向胜率以胜/(胜+亏)计算，清楚剔除平价。
- 重复编号、非法数值、错误时长等会拒绝整份文件，不静默跳过。

数据只在本机进程和网页内存核算，不写入配置或日志，不上传币安或云端；刷新后清除。最多1MB/5000行。程序没有连接币安核验其来源，显示“按导入单点计算”，不是独立认证的交易业绩。导入记录不参与调参。

### 分钟开盘点研究（非真实订单）

为做可重复的历史对照，信号在T时刻收盘形成后，固定延后1分钟取对应指数分钟K线open，再600秒取另一根指数分钟K线open。表里各是一个参考值，显示各自时刻。

这不是你收到手机通知后实际提交的订单，也不是对任意秒位“下一秒开仓”的精确重建。研究命中率不等于实际合约胜率。跨分段和缺失端点记未验证、不按亏；平价净收益0。不会用未来收盘值决定过去的方向。历史研究不作为已验证成功率写入通知。

## 新策略 pullback_v3.0

此策略为自主固定研究假设，不是币安官方推荐；没有用截图或一段行情自动挑参数。

修正v2的三个问题：方向效率保留方向，快速逆转不能靠绝对位移通过；回踩K线必须真正与有限均线带相交，不能整根已经跌破还算“触及”；取消直接追突破，一次回踩最多触发一次。

| 步骤 | 条件 |
| --- | --- |
| 5分钟方向 | 只用完整5分钟线，EMA9/21方向及快线斜率一致，两线分离至少0.1个5分钟ATR |
| 1分钟方向 | EMA9/21同向，至少预热120分钟、21根完整5分钟线 |
| 顺向效率 | 拟交易方向乘以近10分钟净位移，再除以逐分钟绝对位移之和，至少0.25；逆向位移为负 |
| 真实回踩 | 逆向实体K线与此前EMA9±0.15 ATR带相交，收盘不破此前EMA21逆向0.5 ATR结构 |
| 收回确认 | 后1–3根内顺势实体至少0.25 ATR、收回前根EMA9顺势一侧、越过上一根高/低点；每次回踩只触发一次 |
| 不追价 | 当前收盘距**前一根**EMA9不超过1.2 ATR，真实振幅不超过2.5 ATR；ATR用此前14根，不含当前K线 |
| 波动 | ATR/价格在0.02%–0.4% |

看涨看跌镜像。信号只在收盘后60秒内、指数快照不足15秒且距信号收盘价不超过0.5 ATR时有效。检查项数不是概率，也不等于胜率。没有满足条件仍会等待；更严格的不追价可能减少次数，不保证“多且准”。

通知包含方向、触发类型、原因、参考指数、信号时间及参考有效期。手机延迟和人工操作会改变实际提交时间与指数，参考有效期不是承诺成交或盈利。至少601秒信号冷却，推送前保存去重状态，未知结果不自动重发。accepted仅指Bark服务接受，不证明手机展示。

## 本机评估新版与旧版

Mac双击 `evaluate.command`，或运行：

```bash
python3 evaluate.py --days 30 --payout 0.8
```

只读下载指数，不读Bark配置、不推送、不下单。保存 `work/pullback-evaluation.csv` 和 `work/pullback-evaluation.json`。相同时间切分前2/3描述、后1/3验证，对比v2/v3固定规则的分钟参考点命中率和机会数，不自动据此选择/修改参数。部分UTC日不外推频次；不包含实时价差过滤、网络失败、通知和人工下单延迟。

已有指数CSV可用 `--input file.csv`。精确指数端点CSV可用 `--ticks ticks.csv`，已有replay.py按下一秒+600秒验证，缺失端点不补价；调用者仍需核验指数来源，候选回放不等于账户订单。

## 配置与故障排查

网页展开“逐次检查与推送记录”，查看策略版本、检查项、拦截原因、行情年龄和推送accepted/rejected/unknown。配置默认 `~/.config/btc-observer/phone.json`，可用 `BTC_OBSERVER_CONFIG_DIR`指定；日志在同目录logs，按上限轮转，不记录Bark密钥。不要把本地配置提交仓库。

新策略只请求币安指数，不依赖现货量能。缺失、重复、越界K线暂停，不补造。TimeoutError是超时，incomplete_response是断流；HTTP451需核查服务资格或IP误判，不绕过地区限制。Coinbase只作独立现货研究；演示不发送币安合约信号。

程序标准库运行，Python3.10+。开发验证：`python3 -m unittest discover -s tests`；可选Playwright浏览器测试 `python3 tests/browser_v3.py`、`browser_v2.py`、`browser_phone.py`、`browser_refresh.py`。所有设备推送测试使用模拟发送器。

本次验证记录：85项Python回归、15项真实浏览器测试通过，覆盖新旧模式、方向/回踩逻辑、单点统计、缺失数据与平价、CSV同源限制、网页声音/通知、去重及模拟Bark。正式设备通知、24小时运行和真实订单收益尚未验证。云端重新请求fapi公开时间接口仍返回HTTP451，未取得真实行情评估结果，因此不能声称v3已提高成功率。
