# BTC十分钟信号台 · v2.0

本机网页＋Bark手机方向提醒。**新策略是“5分钟趋势＋1分钟回踩/突破”，不是旧五指标的改名或单纯放宽。** 仅研究和发送看涨/看跌信号，不接入账户、不下单、不部署云服务。尚未证明盈利优势，不保证每天出现信号，也不保证成功率。

## 更新后怎么使用

1. 在旧程序终端按Control+C停止。解压新版本到新文件夹，保留旧文件夹和配置。
2. Mac双击 `start.command`；Windows双击 `start.bat`；其他终端运行 `python3 app.py`。打开 http://127.0.0.1:8000 ，页头应为v2.0。
3. 页面上方选择“新策略：5分钟趋势＋1分钟触发”，保持币安BTCUSDT指数，点击“获取分析”。新网页默认选此策略；若读取了旧手机设置，可能恢复旧模式，请手动改为新策略。
4. 点击“保存手机设置”。Bark输入框留空会保留原密钥，无需重填。手机状态栏应显示“新策略：5分钟趋势＋1分钟触发”。再点“发送手机测试”检查实际送达。
5. 网页声音与Mac通知保留；首次运行点击“授权通知 / 启用声音”。后台手机监测约每30秒检查一次，关闭网页也能继续，终端须运行、Mac须联网并保持唤醒。合盖、休眠、关机会中断。

旧配置不会悄悄换策略，需按第3、4步保存一次。新建手机配置默认新策略。停用、重启和留空保存都保留设备密钥、未知配置字段与去重时间。更换策略不会清除冷却期。

本次重新读取英文官方FAQ，页面标注更新于2026-10-28 11:08。规则来源与下面的自主策略必须区分：币安没有为本工具背书，也没有提供这个盈利策略。

- 开仓与到期均比较BTCUSDT**价格指数的单点值**，不是现货最新价、期货成交价或标记价格。
- 官方描述自2026-01-28起逐步使用提交后的下一秒作为开仓时间及指数，十分钟从该开仓时刻再计600秒。例如17:59:59提交，18:00:00开仓，18:10:00到期；任意毫秒提交并非都固定601秒。

- 赔付比例动态变化，在提交订单时锁定。页面默认80%是**净收益假设**：投入1，赢净赚0.8、输亏1、平0；不是官方固定赔率。无平价时对应盈亏平衡胜率55.56%。

## 新策略定义：trend_v2.0

以下数字是预先固定的研究假设，没有用一段行情调成“高胜率”。上下方向完全镜像。只用连续已收盘指数K线，预热至少120分钟及21根完整5分钟K线；5分钟线按交易所UTC五分钟边界聚合，当前未结束的5分钟线不使用。

| 步骤 | 固定判断 |
| --- | --- |
| 5分钟方向 | EMA9在EMA21之上且EMA9上升，看涨；反之看跌。两线分离至少0.1个5分钟ATR |
| 1分钟确认 | EMA9/21与5分钟方向一致 |
| 横盘过滤 | 近10分钟净位移÷逐分钟绝对位移总和至少0.25 |
| 波动过滤 | 此前14分钟真实振幅均值ATR/当前价格在0.02%–0.4% |
| 不追价 | 当前价格距1分钟EMA9不超过1.8 ATR，当前真实振幅不超过2.5 ATR |
| 回踩重启 | 前3根中触及各自EMA9附近0.15 ATR，收盘保持当前EMA21附近0.5 ATR内；当前顺势收盘越过上一根高/低点并回到EMA9顺势一侧 |
| 区间突破 | 当前收盘顺势越过此前5根最高/最低点 |
| 触发实体 | 回踩或突破均要求顺势实体至少0.25 ATR |

最后两类触发有一类成立即可。前面的趋势、效率、波动和不追价必须满足。成交量与RSI不是硬条件。此前ATR排除当前K线，防止突发大K线把自己的波动过滤阈值撑大。检查项数不是概率。

新策略不受旧版“后段至少30笔且Wilson下界过门槛”限制。触发后仍要求：指标收盘不足60秒、当前指数快照不足15秒、指数距信号收盘价不超过0.5 ATR；否则WAIT并记录取消原因。**有效时间是参考截止时间，不是保证在此之前能成交或仍有优势。** 手机送达和人工提交有延迟，订单实际价格可能变化。

每次通知含看涨/看跌、回踩重启/区间突破、触发原因、参考指数、指标基准、参考有效期和规则说明。同一信号不重复；至少601秒冷却，不因为策略切换重置。保存去重状态后才尝试推送，结果未知时不会自动重发。Bark accepted只代表服务接受，不证明手机展示。

## 数据与历史研究

新策略只读 `fapi.binance.com/fapi/v1/time`、`/fapi/v1/indexPriceKlines?pair=BTCUSDT&interval=1m`、`/fapi/v1/premiumIndex?symbol=BTCUSDT` 的indexPrice，不再因现货量能接口失效阻塞。指数K线第六字段是Ignore，忽略它；Candle.volume置0表示本策略不使用成交量，不表示真实成交量为0。旧策略仍独立请求并对齐现货量能，缓存与新策略隔离。任一指数页缺失、重复或越界则暂停，不补价、不改用其他价格。

界面主区展示当前信号与原因，历史范围折叠。**真实订单为单点结算；历史分钟高低范围只是无法精确重建秒级端点时的不确定界限。** 未将这些范围替换为虚构的精确开仓/到期价或胜率。

Mac双击 `evaluate.command`，或运行：

```bash
python3 evaluate.py --days 30 --payout 0.8
```

只读下载指数，保存 `work/trend-evaluation.csv` 和 `work/trend-evaluation.json`，不读取Bark配置、不发通知。时间顺序前2/3描述、后1/3验证，显示每日候选/冷却后机会、确定胜负、未知数、盈亏上下界；不自动选择或修改参数。部分UTC日不外推频次。此结果不是逐次滚动的生产推送回测，不包含实时价差过滤、网络失败及人工下单延迟。

已有指数CSV可传 `--input file.csv`。另有精确指数端点CSV时可传 `--ticks ticks.csv`（time_ms,index_price），按下一秒开仓及600秒到期做候选验证，缺失端点不补价；并不等于账户真实交易。旧版compare.py仍保留用于独立旧条件研究。

## 网络和诊断

网页展开“逐次检查与推送记录”，可见检查次数、策略、触发类型、逐项不通过原因、行情延迟、HTTP诊断与推送尝试/accepted/rejected/unknown。配置默认 `~/.config/btc-observer/phone.json`，通过 `BTC_OBSERVER_CONFIG_DIR`可指定目录；日志在同目录logs，轮转且不记录Bark密钥。请勿将本地配置上传仓库。

浏览器能打开接口不等于Python相同网络路径稳定。TimeoutError表示超时，incomplete_response表示断流；HTTP451请检查地区资格或IP误判，429/418请降低频率并等待。不会绕过地区限制。Coinbase仅独立现货研究，合成演示永远不推送币安合约信号。
